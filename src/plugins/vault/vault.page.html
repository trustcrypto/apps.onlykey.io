Hardware-encrypted credential vault with OnlyKey

Store API keys and secrets encrypted by your OnlyKey. Encryption keys are derived on the device, and only ciphertext is stored, in this browser.

How your secrets are encrypted
  • Format: each secret is a standard age file encrypted to an ML-KEM-768 + X25519 (X-Wing) key, the post-quantum hybrid age uses natively. It is the same derived key and file format as the age page and age-plugin-onlykey.
  • On the OnlyKey: for each service name the device derives an X-Wing key pair from its web-derivation key, a random 32-byte key generated on the OnlyKey, and SHA-256("vault:" + service name). The private key never leaves the OnlyKey.
  • Store: this page gets the service's public key from the OnlyKey (no tap needed) and writes the age file here: X-Wing (HPKE) wraps a random file key, and the secret is encrypted with ChaCha20-Poly1305. Only the age file is stored, in this browser (IndexedDB).
  • Unlock: the file's X-Wing ciphertext goes to the OnlyKey, which decapsulates it (both the ML-KEM and the X25519 halves) and returns the shared secret over the encrypted OnlyKey connection. Every unlock needs a tap, or the challenge code shown below if your OnlyKey is set to challenge mode. Unlocked entries stay open in memory for the session time you choose, until Lock all sessions or the page closes.
  • Command line: Copy age file and Copy age identity give you the file and an identity line; with age-plugin-onlykey installed, age -d -i identity.txt secret.age opens it with the same OnlyKey.
  • Recovery: the same OnlyKey and service name always give the same key pair, so an exported vault opens on any computer with that OnlyKey, or with a key restored from its backup.
